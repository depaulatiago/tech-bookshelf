## Resumo

Programação funcional (PF) é um paradigma que constrói programas compondo **funções puras**. O resultado de uma função pura depende só da entrada, e ela não altera nada fora de si. Os dados são **imutáveis**, as funções são **valores** que podem ser passados adiante, e os **efeitos colaterais** (E/S, mutação, exceções) ficam isolados nas bordas do programa. O principal ganho é um código mais fácil de entender, testar e combinar, o que pesa mais conforme o projeto cresce.

## Conceitos-chave

### Imutabilidade

Depois de criado, um valor nunca muda. Para "modificá-lo", cria-se um novo valor a partir do antigo. Isso elimina toda uma classe de bugs: estado compartilhado que muda de forma inesperada, principalmente com concorrência.

```scala
val xs = List(1, 2, 3)
val ys = xs :+ 4   // nova lista; xs continua List(1, 2, 3)
```

### Transparência referencial

Uma expressão é referencialmente transparente quando pode ser substituída pelo seu resultado sem mudar o comportamento do programa. Funções puras garantem isso: `add(2, 3)` sempre pode virar `5`. Assim dá para raciocinar sobre o código localmente, como em álgebra.

```scala
def add(a: Int, b: Int): Int = a + b   // transparente

var total = 0
def addToTotal(n: Int): Int = { total += n; total }   // não transparente: depende de estado oculto
```

### Funções de alta ordem

Funções são valores: podem ser passadas como argumento e retornadas como resultado. Uma função de alta ordem recebe ou devolve outra função. `map`, `filter` e `fold` substituem a maior parte dos laços manuais.

```scala
val nums = List(1, 2, 3, 4)
nums.filter(_ % 2 == 0).map(_ * 10)   // List(20, 40)

def twice(f: Int => Int): Int => Int = x => f(f(x))
twice(_ + 3)(1)   // 7
```

### Avaliação preguiçosa

Uma expressão só é avaliada quando seu valor é realmente necessário. Isso evita trabalho desnecessário e permite estruturas infinitas.

```scala
lazy val caro = { println("calculando..."); 42 }   // executa só no primeiro uso

val naturais = LazyList.from(1)
naturais.map(_ * 2).take(3).toList   // List(2, 4, 6)
```

### Pensando como um programador funcional

- Descrever **o que** calcular (transformações sobre dados), e não **como** percorrer passo a passo
- Quebrar problemas em pequenas funções puras e **compô-las**
- Tratar efeitos colaterais como algo a isolar, não a espalhar pelo código
- Modelar dados com tipos imutáveis e deixar os tipos guiarem o design

### Os benefícios da PF

- **Mais fácil de entender:** sem estado oculto, cada função pode ser compreendida isoladamente
- **Mais fácil de testar:** mesma entrada, mesma saída, sem preparar estado nem criar mocks
- **Concorrência mais segura:** dados imutáveis podem ser compartilhados entre threads sem locks
- **Reuso e composição:** funções pequenas e genéricas se combinam em comportamentos maiores

#### A PF pode aumentar a produtividade?

A curva de aprendizado inicial existe, mas gasta-se menos tempo depurando bugs de estado e tentando entender o que o código faz. Os programas também tendem a ser mais curtos.

#### A PF é divertida

Resolver problemas compondo peças pequenas e corretas dá uma satisfação quase matemática. Também muda a forma de pensar em qualquer linguagem.

### Scala

O livro usa Scala: linguagem da JVM que mistura orientação a objetos e programação funcional. Tem coleções imutáveis por padrão, funções de primeira classe, pattern matching e um sistema de tipos forte, o que a torna um jeito prático de aplicar PF em projetos reais.
